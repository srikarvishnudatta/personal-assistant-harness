The everyday loop

  1. You ask through the Astryx chat UI.
  2. The Python agent reads relevant memory and uses bounded tools.
  3. Consequential writes become exact approval cards.
  4. Background jobs and agent teams checkpoint in SQLite.
  5. Results and execution records appear in Inbox.

Durability

Completed stages remain reusable. Interrupted stages can be requeued after a restart. Explicit retries are bounded to three attempts per failed agent.

Recovery can repeat an interrupted model call and incur another charge. Persisted checkpoints are not a guarantee of exactly-once external effects.

Permissions and capacity

Team agents are read-only: no sends, memory/file changes, approvals or further delegation. Up to two background model calls can run concurrently, subject to available token reservations.

Cancellation stops queued and running agents. The server must stay running for progress.

Memory with a history.

SQLite is authoritative. Human-readable files are managed projections. Corrections, source IDs and confidence make saved claims inspectable.

Layers

  • Raw conversation history
  • Bounded context summary
  • Curated saved claims and revision lineage
  • Managed MEMORY.md, daily notes and person notes
  • Reviewable dream proposals

Retrieval

Keyword search and bounded GPT-6 Luna ranking retrieve saved claims. Full semantic search across every past transcript is still future work.

Dream application checks the memory revision used to create it; stale proposals must not silently replace newer corrections.

What happens when I ask it to forget?

The pipeline removes the recorded claim and revision history, redacts known exact derived copies, invalidates summaries, and can remove known source messages when explicitly requested.

Unrelated paraphrases, backups and external copies may remain. Projection refresh failures are reported, and stale managed files are blocked from tool reads.

Propose. Review. Execute.

A tool proposal and a successful external action are separate records.

Approval contract

  1. Save an immutable payload, digest and expiry.
  2. Show the exact destination and operation for review.
  3. Accept or reject against the expected digest.
  4. Atomically claim execution once.
  5. Record outcome and audit evidence.

When the outcome is uncertain

An interrupted external write is held for checked reconciliation. Reconciliation records evidence; it does not send the action again.

Browser approval is tied to the observed page URL. A changed page or mismatched digest must block execution.

Browser operation and manual login

The assistant owns a persistent Playwright Chromium profile. Open a manual window to enter credentials yourself; agent operations stop during manual control. Returning control restarts the dedicated context and tab IDs may change.

Public address validation and request interception block private destinations and unapproved ordinary POST writes during automation. This is not an OS network sandbox; GET side effects and DNS races remain limitations.

Google, credentials and optional code execution

Google needs your own OAuth client, consent screen configuration and completed consent. Gmail sending and Calendar creation also need an exact action approval. Keep the existing HARNESS_TOKEN if it protects your vault; configure CREDENTIAL_KEY deliberately before changing it.

No host-shell tool is exposed. Docker scripts require explicit opt-in and a preloaded image; they run with no network, a read-only workspace mount and bounded resources/time.

Run it. Verify it.

PowerShell commands for the project root. Stop the previous server before switching runtimes or using the same SQLite state.

Keep the server running in a separate terminal for HTTP smoke tests. After the first local smoke phase, restart it before running restart verification. Tests use synthetic fixtures; audit records are intentionally retained.
Google connection setup
  1. Create a Google Cloud web OAuth client and enable Gmail and Calendar APIs.
  2. Configure consent/test users and callback http://127.0.0.1:8787/oauth/google/callback (adjust the port if needed).
  3. Set GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET in .dev.vars.
  4. Restart, open Connections and complete consent.
  5. Verify a bounded read before reviewing any write proposal.

Troubleshooting

Cannot reach the local API

Keep npm run dev running. Confirm its ready log and LOCAL_PORT. A compiled build does not imply the server is running.

DNS or browser failure

Run npm run doctor:network in the same terminal. A browser launch does not prove navigation. Keep public-address validation enabled.

Existing smoke fixture

If phase one completed, restart and run npm run test:local -- --verify-restart. For incomplete fixtures, wait until the queue is idle before --cleanup.

Windows file permissions

Use your normal terminal when the restricted session cannot replace dist files or install dependencies. A second server must not recover the same live database.
